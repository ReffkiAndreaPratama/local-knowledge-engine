# API reference

The backend exposes a JSON API under `/api`. Interactive documentation is served
by FastAPI at **`/api/docs`** (Swagger UI) and **`/api/redoc`** while the server is
running. This page summarises the endpoints, the important request fields and the
error behaviour.

Base URL in development: `http://127.0.0.1:8000/api`.

All request and response bodies are JSON except `POST /api/documents/import`,
which is `multipart/form-data`.

## Conventions

- Lists use `{ "items": [...], "total": <int> }` and accept `skip`/`limit`.
- Errors use FastAPI's default shape: `{ "detail": "message" }` with status
  `400`, `404`, `409`, `422` or `500`.
- Timestamps are ISO-8601 strings.
- IDs are UUID strings generated by the backend.
- The API has **no authentication** and is intended to bind to `127.0.0.1` only.
  Do not expose it to a network without adding an authenticating reverse proxy.

## Health

### `GET /health/`
```json
{ "status": "healthy", "database": "connected" }
```
Returns `unhealthy` with an `error` field if the database check fails. The process
still returns HTTP 200 so a simple monitor can distinguish "up but degraded".

## Documents

### `POST /documents/import`
`multipart/form-data` with one or more `files` parts.

```bash
curl -F "files=@notes.md" -F "files=@report.pdf" \
  http://127.0.0.1:8000/api/documents/import
```

```json
{
  "job_id": "4b1f...",
  "accepted": ["notes.md", "report.pdf"],
  "rejected": [{ "filename": "huge.zip", "reason": "Unsupported file type: .zip" }],
  "queued_count": 2
}
```

Files are validated (extension, size, non-empty), copied into
`backend/data/documents/`, and indexed by a background job. A file whose SHA-256
already exists is skipped but reported in `accepted`. Poll the job or the document
list for completion.

### `POST /documents/import-folder`
```json
{ "directory": "C:/Users/me/notes", "recursive": true }
```
The directory must be inside one of the allowed import directories (see
[Settings](#settings)); otherwise the API returns `400`. Hidden files, common
dependency folders and unsupported extensions are skipped. Returns the same shape
as `/import`.

### `GET /documents`
Query params: `skip` (default 0), `limit` (1–500, default 100), `filename`
(substring), `extension` (e.g. `.pdf`), `status`
(`pending|processing|completed|failed`).

```json
{
  "items": [{
    "id": "9380...",
    "filename": "atlas-onboarding.txt",
    "extension": ".txt",
    "original_path": "data\\documents\\68c5....txt",
    "file_hash": "7cc6...",
    "file_size": 1326,
    "parsing_status": "completed",
    "indexing_status": "completed",
    "parsing_error": null,
    "page_count": null,
    "char_count": 1325,
    "chunk_count": 4,
    "imported_at": "2026-10-27T15:51:44",
    "last_indexed_at": "2026-10-27T15:51:45.532519"
  }],
  "total": 1
}
```

### `GET /documents/{document_id}`
Returns one document or `404`.

### `GET /documents/{document_id}/chunks`
Paginated chunk list. Each chunk includes `content`, `chunk_index`, `page_number`,
`heading`, `start_char`, `end_char` — the data used by the source preview.

### `DELETE /documents/{document_id}`
Removes the database row, its chunks, FTS rows, embeddings and the managed copy of
the file. The original file outside `data/documents/` is never touched.

### `POST /documents/{document_id}/reindex`
Queues a re-index job for one document: `{ "job_id": "..." }`.

### `POST /documents/reindex`
```json
{ "document_ids": ["<id>", "<id>"] }
```

### `POST /documents/scan-changes`
Compares stored hashes with the files still on disk. Returns counts for changed,
unchanged and missing files and queues re-indexing for changed ones.

## Search

### `POST /search/`
```json
{
  "query": "How long do access tokens last?",
  "mode": "hybrid",
  "limit": 20,
  "offset": 0,
  "filters": { "document_ids": null, "extensions": [".md"] },
  "fts_weight": 1.0,
  "semantic_weight": 1.0,
  "max_per_document": 2
}
```

| Field | Notes |
|-------|-------|
| `mode` | `fulltext`, `semantic` or `hybrid` |
| `limit` | 1–100 |
| `filters.extensions` | Optional list such as `[".md", ".pdf"]` |
| `fts_weight`, `semantic_weight` | RRF weights for hybrid mode (0–10) |
| `max_per_document` | Per-document chunk cap (1–20, default 2) |

```json
{
  "query": "How long do access tokens last?",
  "mode": "hybrid",
  "total": 1,
  "elapsed_ms": 1.83,
  "results": [{
    "chunk_id": "…",
    "document_id": "…",
    "document_name": "atlas-security.md",
    "extension": ".md",
    "content": "Production access uses short-lived tokens … expire after 60 minutes …",
    "snippet": "… expire after \u0001 60 minutes \u0002 …",
    "page_number": null,
    "heading": "Access control",
    "score": 0.0325,
    "highlights": ["60 minutes"],
    "explanation": "matched by keyword and semantic rank"
  }],
  "notes": []
}
```

`notes` always explains a degraded result, e.g. semantic search was requested but
the embedding model is not available. It is never silently empty in that case.

## Indexing jobs

### `GET /indexing/jobs`
Filters: `skip`, `limit`, `status`. Newest first.

### `GET /indexing/jobs/{job_id}`
Returns `status` (`pending|running|completed|failed|cancelled`), `job_type`,
`total_files`, `processed_files`, `failed_files`, `current_file`, timestamps and
`error_message`.

### `POST /indexing/jobs/{job_id}/cancel`
Requests cancellation. The worker checks the flag between files; the current file
finishes first.

## AI assistant

### `POST /assistant/ask`
```json
{
  "question": "Which port does the Atlas API use?",
  "mode": "hybrid",
  "limit": 6,
  "provider": null,
  "consent_to_external_provider": false
}
```

```json
{
  "answer": "The Atlas API listens on port 8080 by default [1].",
  "sources": [{
    "index": 1,
    "chunk_id": "…",
    "document_id": "…",
    "document_name": "atlas-handbook.md",
    "page_number": null,
    "heading": "Deployment",
    "excerpt": "The Atlas API listens on port 8080 by default. …",
    "score": 0.03
  }],
  "provider": "ollama",
  "model": "llama3.2",
  "grounded": true,
  "insufficient_evidence": false,
  "invalid_citations": [],
  "warning": null,
  "retrieval_mode": "hybrid",
  "notes": []
}
```

Key guarantees:

- Retrieval runs first. If nothing relevant is found, the answer is the fixed
  `insufficient_evidence` message with an empty `sources` list.
- Citations are validated against the retrieved sources. Unknown `[n]` markers are
  removed and listed in `invalid_citations`; `grounded` becomes `false`.
- An answer that contains no valid citation is not presented as grounded.
- External providers require `consent_to_external_provider: true`; without it the
  request fails with `400` and a readable message.
- If the provider is disabled, missing or unreachable, the response falls back to
  retrieved sources with a `warning` instead of inventing an answer.

## Settings

### `GET /settings`
Returns the effective, non-secret configuration: allowed import dirs, limits,
chunking, supported extensions, semantic/assistant flags, model names, consent and
history settings. API keys are never returned.

### `PUT /settings`
Partial update; unknown or secret fields are rejected by validation. Editable
fields: `allowed_import_dirs`, `max_file_size_mb`, `chunk_size`, `chunk_overlap`,
`enable_semantic_search`, `embedding_model`, `enable_ai_assistant`, `ai_provider`,
`ai_model`, `ollama_base_url`, `require_ai_consent`, `store_search_history`.

Values are persisted in SQLite and override environment defaults for the running
process. Some values (chunk size, model) apply to subsequently indexed documents;
existing documents keep their current chunks until re-indexed.

### `DELETE /settings/search-history`
Deletes stored queries and latencies. Documents, chunks and embeddings are not
affected.

## Analytics

### `GET /analytics/stats`
Local-only counters: document/chunk counts, total source bytes, indexed/failed/
pending documents, query count, average response time, embedding count and model,
embedding coverage percentage, last indexed timestamp and storage backend.

Nothing is transmitted anywhere; the endpoint only reads SQLite.

## Collections

| Method | Path | Purpose |
|--------|------|---------|
| `GET` | `/collections` | List collections with document counts |
| `POST` | `/collections` | Create `{ "name", "description" }` (409 on duplicate name) |
| `GET` | `/collections/{id}` | Get one collection |
| `DELETE` | `/collections/{id}` | Delete collection (documents are not deleted) |
| `GET` | `/collections/{id}/document-ids` | `{ "document_ids": [...] }` |
| `POST` | `/collections/{id}/documents` | `{ "document_ids": [...] }` add members |
| `DELETE` | `/collections/{id}/documents/{document_id}` | Remove one member |

Collections are virtual; membership does not move or copy files.

---

## Saved searches

| Method | Path | Purpose |
|--------|------|---------|
| `GET` | `/saved-searches` | List saved searches |
| `POST` | `/saved-searches` | `{ "name", "query", "search_mode" }` |
| `DELETE` | `/saved-searches/{id}` | Delete one |

Saved searches are templates; the UI re-runs the query when opened.

## Not implemented

- Authentication/authorisation.
- Streaming assistant responses.
- Bulk export of search results.
- Pagination cursors (offset pagination only).
- PostgreSQL search backends (see [architecture.md](architecture.md)).
