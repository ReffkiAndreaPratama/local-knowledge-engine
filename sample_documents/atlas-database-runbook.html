Atlas Database Failover Runbook

Synthetic sample content for Local Knowledge Engine testing. Atlas is a fictional product.

When to fail over

Fail over when the primary database has been unreachable for more than five minutes and the replica is healthy. Announce the decision in the incident channel before changing traffic.

Procedure

  1. Confirm replication lag is below 10 seconds.
  2. Pause background workers with the maintenance switch.
  3. Promote the standby using the managed failover command.
  4. Point the application at the new primary and restart the API pods.
  5. Run the read-only smoke checks and watch error rates for 15 minutes.

Rollback

If the new primary fails health checks, stop traffic, restore the previous connection string, and escalate to the database on-call. Never run two primaries at the same time.
